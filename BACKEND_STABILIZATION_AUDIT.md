# IshuriHUB Backend Stabilization Audit

**Audit date:** 2026-10-31  
**Scope:** Repository state at `d982911`, including 14 ordered Supabase migrations, 15 pgTAP files, four Supabase Edge Functions, Supabase configuration, frontend Supabase services/types, and the legacy Express/Prisma backend. This report was written before backend remediation began.

## Executive findings

The Supabase schema has a strong default-deny foundation: static review found 44 created tables, all with RLS enabled and forced; scoped composite foreign keys are used extensively; and SECURITY DEFINER functions use an empty search path and explicit ownership/grant statements. The two previously reported migration defects are already fixed in commits `00c8e98` (self-delegation seeds) and `d982911` (`v_local_time`). Static scanning found no remaining undeclared `v_*` local variables.

The audit found one additional broken write path in student registration, one invalid-time-zone configuration path that can later break attendance timestamps, a mismatch between the card-list RPC and generated TypeScript contract, and gaps between several backend workflows and the current frontend identity/workflow. The local database is unavailable, so SQL compilation, pgTAP execution, and Edge Function runtime behavior could not be verified.

## Migration and schema audit summary

- 14 Supabase migrations are present in timestamp order. Static dependency review found base identity/role/academic/attendance/card schemas precede the workflows that use them; no duplicate `CREATE TABLE` definitions were found.
- 44 tables are created; static scan found RLS enabled and forced on all 44. Scoped foreign keys and checks are extensive, including same-school actor, student, assignment, and event references.
- 61 PostgreSQL functions are declared. Static scan found no currently undeclared `v_*` locals; SECURITY DEFINER declarations use `SET search_path = ''`, explicit `postgres` ownership, and role-specific execute grants/revokes in the migration sources.
- `20261031135147_seed_scoped_permissions_and_role_workflows.sql` excludes school-manager self-delegation and no longer seeds organization/platform self-edges (commit `00c8e98`).
- `20261031141234_trusted_attendance_workflows.sql` declares `v_local_time time` (commit `d982911`). `process_attendance_scan` converts both date and time using the school settings time zone and compares local time with `school_day_start`; this logic is coherent for valid time-zone values.
- A static parser for `INSERT ... (columns) VALUES (...)` found one count mismatch: student registration has 11 target columns and 10 values (DB-01).
- Supabase configuration targets PostgreSQL 17, exposes only `public` and `graphql_public`, leaves migrations enabled, and sets `verify_jwt = false` only for the device-authenticated attendance scan function. That function checks an active stored device credential before the service-role RPC.

## Prioritized remediation plan

1. **Batch 1 — restore registration and deterministic date handling:** correct DB-01, add a pgTAP success test, validate school time zones (DB-02), and add a pgTAP invalid-zone test.
2. **Batch 2 — close verification blind spots:** add behavior tests for student registration/activation prerequisites, guardian lifecycle, staff/teacher assignment, scan/device auth/idempotency/time-zone boundaries, and card lifecycle/audit. Establish a local non-destructive test runtime first.
3. **Batch 3 — align browser identity with database identity:** migrate the frontend session to Supabase Auth; wire student activation and guardian flows; make role/school context server-derived. This is a frontend-owned dependency and cannot be completed in this backend-only change set.
4. **Batch 4 — harden Edge Function contracts:** fix scan CORS/preflight, return a bounded accepted/rejected/duplicate outcome, pin Deno dependencies, and add function-level tests. Requires function test harness and coordinated UI contract update.
5. **Batch 5 — settle the dual-stack boundary:** classify legacy Express modules as retained or migrated; replace the fixed backend origin with environment configuration; decide which database owns school/student/staff/card writes and document backfill/reconciliation.
6. **Batch 6 — resolve security/configuration and scale risks:** restore PostgreSQL certificate verification, tighten CORS to exact trusted origins, define school-local date semantics, and load-test paginated roster/list workflows.

## Remediation status

This audit was recorded before code changes. Batch 1 corrected the confirmed registration column/value alignment defect in `register_student_from_edge` and added a pgTAP workflow test for registration persistence, membership/role linkage, pending status and audit logging (`1fb64d3`).

### Remediation batch 2

- **DB-02:** a new migration validates existing settings against `pg_catalog.pg_timezone_names` and installs a `BEFORE INSERT OR UPDATE OF timezone` trigger. Invalid names raise SQLSTATE `22023`; the existing `update_school_settings` permission check remains in place. pgTAP now covers accepted `Africa/Kigali`, rejected `Mars/Olympus`, and preservation of the prior value.
- **DB-04 / DB-05:** `process-attendance-scan` handles trusted-origin `OPTIONS` preflight, allows only configured exact origins and the required `x-device-credential` header, and applies CORS headers to success and error responses. A service-role-only outcome RPC exposes only event UUID, `accepted`/`rejected`/`duplicate`, and a bounded rejection code. Device credential verification, device school scope, HMAC card identifier handling, idempotency and SQL authorization remain intact.
- **ARCH-02:** all four Edge Function imports are pinned to `@supabase/supabase-js@2.95.0`. Per-function `deno.json` and integrity-bearing `deno.lock` files use frozen resolution. Explicit `--config` resolves the earlier Deno workspace-config problem.
- **TEST-02 / TEST-03:** pgTAP now includes time-zone validation; student registration and guardian invite/accept/approve effects; staff registration and cross-school denial; school-local virtual tap date/time, replay and duplicate behavior; and card issue/activate/suspend/audit plus accepted, unknown-card, inactive-card, invalid-device, wrong-school and idempotent NFC scan cases. The Edge handler has mock-backed tests for accepted/rejected/duplicate responses, invalid credential, allowed preflight, origin rejection, CORS and response identity minimization.
- **Execution:** Deno type-checks for all four Edge Functions and the scan tests passed; all six Edge handler tests passed. Static assertion counts match the pgTAP plans in suites 010 through 014. `supabase test db --local` and `supabase migration list --local` could not connect (`ECONNREFUSED 127.0.0.1:54322`), so no SQL migration or pgTAP behavior has been runtime-verified. No database was started, reset, or modified.
- **Configuration dependency:** the scan Edge Function defaults to exact localhost origins. Deployment must set `ATTENDANCE_SCAN_ALLOWED_ORIGINS` to the exact approved application origins; production configuration was not changed or verified.

The architecture proposal for Supabase Auth and existing Express account linking is recorded separately in `SUPABASE_IDENTITY_MIGRATION_PROPOSAL.md` and committed as `17bc400`. No identity migration or frontend change was implemented.

Remaining audit items include AUTH-01 and AUTH-04 (frontend Supabase session and student activation integration), AUTH-02/AUTH-03 (legacy PostgreSQL TLS and CORS), DB-03/DB-06 (frontend card type and student-detail contract), API-01 through API-03 (legacy API routing and workflow ownership), TEST-01 (frontend testing-center false positives), incomplete coverage within TEST-02/TEST-03, ARCH-01 (dual-stack cutover), TIME-01, and PERF-01. Migration and pgTAP runtime verification remains blocked by the unavailable local database. The identity proposal is not an implementation or production migration approval.
